# Things to build on NMTS

NMTS stores files end-to-end encrypted on the Walrus network. The SDK (`@needmoretruth/nmts-sdk`, Apache-2.0) gives a program the same storage a person gets at nmts.me. NMTS charges nothing and takes no cut; storage is paid to the Walrus network from a wallet. What follows are products one person or a small team could build on it. They are ideas, given away: build them, change them, sell them. If you copy this text, credit needmoretruth and link to nmts.me (CC BY 4.0). NMTS does not inspect, certify or vouch for what is built on it.

Each idea says who holds the key, because that decides who can read the files: the person (`Nmts.device`, also in a page), or your service (`Nmts.managed`).

1. **Encrypted backup for a self-hosted app.** A plugin for a wiki, a photo library or a password manager that pushes nightly archives. Key: the person. Calls: `put`, `list`, `get`, `extend` before leases run out, `erase` for rotation. The S3 gateway recipe lets rclone, restic or a framework's storage adapter do the same with no new code.
2. **A file drop for a newsroom or a clinic.** A page where an outsider hands over a document that the organisation keeps encrypted. Key: the organisation, in a managed store. Today the document goes through the organisation's server, which calls `put` on the managed account — so that server sees the document on its way in, and the page should say so. *Not yet in the SDK:* sharing from one account to another, which would let the outsider's device encrypt straight to the organisation with no server in between. Today sharing is the command-line tool's.
3. **Storage for an AI agent.** An agent keeps its working files and memory in an account of its own and pays from its own wallet. Key: the agent's machine. Calls: the MCP server in `nmts-cli`, or `put(…, { pay: "wallet", dryRun: true })` to see the price before it spends.
4. **Private storage inside your own product.** Notes, recordings, design files — your users never visit nmts.me. Key: either, and you say which to your users. Calls: `Nmts.business`, `registerUser` or `registerWithDelegation`, then every method through a delegation token.
5. **A storage service that takes payment its own way** — card, Lightning, Monero — and pays the network from a wallet it keeps funded. Key: the person. Calls: `registerWithDelegation` for each user; the service cuts a piece from a storage resource it holds and hands it to the user's account wallet with `splitStorage` and `transferStorage`; the user's device uploads with `put(…, { pay: "wallet", storage: id })`. *Not yet in the SDK:* paying for a user's upload inside the user's own transaction, buying a storage resource without uploading, and a price for a size and a period without a file.
6. **A dead-man's archive.** Files that must outlive a person's attention: leases extended on a schedule from a funded wallet, a recovery kit kept by someone the person trusts. Calls: `storage()`, `extend`, and the recovery kit from the command-line tool. *Not yet in the SDK:* making the recovery list.
7. **Evidence that a file existed.** Walrus blobs are registered on the Sui chain with a time. A product can store a sealed file and later show when it was stored, without showing the file. Calls: `put`, then the blob's on-chain record. Say exactly what this proves: that these encrypted bytes were stored at that time — not who wrote them, and not what they say unless the key is shown.
8. **Wallet-native storage for a Sui app.** A game or a dApp lets a player log in with the wallet they already use and keeps their saves or assets encrypted. Calls: `nmts.openers.addWallet` once, then `Nmts.fromWallet` on every visit — one signature, and the NMTS key stays the account's root.

What none of these can do, because NMTS cannot: recover a lost NMTS key, read a user's files on a server's behalf when the key is on the user's device, or keep files alive after their storage term ends unpaid.
